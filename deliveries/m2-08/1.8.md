# Work Order 1.8 -- NSE mid-cap panel, phase E1: data, universe, cost and tax rules (no tests)

Issued by the mathematician (M2), 2026-10-29, for developer D2. Follow `docs/PROTOCOL.md` exactly. Still in force and not repeated:
Work Orders 1.5 to 1.7 and the rulings in `docs/correspondence/` (R1-R4, the cutoff and holdout mechanics, A1-A6, mistakes 8, 10,
14, 15, 18, 19, 21). This order is the first step of the owner's expansion roadmap (NOTES.md section 10); it is short on purpose.

Stop point: the data store, the universe file, the validation report and the two rules files are committed. NO relationship between
any predictor and any return is computed in this phase (descriptive validation only): the candidate families are pre-registered in
Work Order 1.9 before anyone looks at a single equity return. The holdout stays untouched.

## 0. Decisions of the owner (2026-10-29) and limits

- Market: NSE equities, mid-caps first, 30 names, daily bars first (weekly and monthly are derived from daily). The same cutoff,
  2025-08-31, and a one-shot holdout per candidate, exactly as for crypto. Everything is pre-tax and labelled so until a tax rules
  file is confirmed.
- Data: the owner's Upstox API access (something the owner already has: allowed by hard limit 1) and the owner's Postgres. Per
  Upstox's own documentation and community notes (read 2026-10-29): daily, weekly and monthly history from January 2000; minute-level
  history only from January 2022 (so intraday is a later, short-sample phase); prices are adjusted for splits and bonuses by Upstox but
  not always correctly (demergers have been reported unadjusted) and are re-adjusted over time; dividends are not in the prices.
  Hence: every pull is stored once, dated and hashed, and never overwritten.
- Secrets: the Upstox token and the Postgres credentials are never read, printed or committed by any agent (same rule as
  `temp/secret_keys.txt`); scripts read them from the owner's environment.

## 1. Universe (M2 draws, you consume)

- Input: the AMFI list "Average market capitalization of listed companies, six months ended 2025-06-30" (published July 2025, in force
  on the cutoff); mid caps are ranks 101-250. The owner supplies the Excel file to M2. An optional owner exclusion file
  (`universe/owner-exclusions.txt`, one symbol per line, committed BEFORE the draw) removes names the owner will never trade.
- M2 delivers `universe/nse-midcap-draw-v1.csv`: every eligible mid cap in a seeded random order (seed 20250831): draw_order, company,
  nse_symbol, isin, amfi_rank, average_market_cap. You take companies in draw order and keep the first 30 that pass the data rule:
  first daily candle on or before 2015-08-31 (at least ten years before the cutoff), at least 95% of the trading days present from the
  first candle to the cutoff, no unresolved jump flag (section 3). Every skip is logged with its reason. No hand picking. The final list
  `universe/nse-midcap30-v1.csv` is committed before any statistic is computed.
- Survivor bias is real and accepted (a 2025 list cannot hold companies that dropped out or were delisted since); results are read
  against buy-and-hold of the same names (Work Order 1.9).

## 2. Data format and store

- One CSV per symbol, `data/nse/1d/pull-<YYYYMMDD>/<SYMBOL>.csv`: `date` (YYYY-MM-DD, the IST trading date, no time zone),
  `open`, `high`, `low`, `close`, `volume`, ascending, prices in INR as delivered. A `manifest.json` per pull: symbol, rows, first and
  last date, SHA-256, pull time, source (API or Postgres table). A re-pull is a new folder; every later record cites the manifest hash.
- Export from the owner's Postgres: a read-only script that you write after the owner pastes the table description (`\dt`, `\d <table>`,
  three sample rows). Direct API pulls are the fallback and respect Upstox's rate limits and per-call date limits (chunk the calls).
- Cutoff and holdout: the loader truncates at 2025-08-31 (calendar date) before any computation; data after the cutoff is stored in a
  separate file that only the forward-test command may read (the crypto hooks, A2, generalised by market).

## 3. Validation report (descriptive only)

Per symbol: first and last date, rows, missing trading days (the trading calendar is the set of dates on which at least half of the
pulled symbols have a candle), duplicate or non-monotone dates, OHLC consistency (low <= open, close <= high, positive prices),
zero-volume days (a zero-volume bar is a placeholder, not an observation: masked like a missing bar, mistake 21), and JUMPS: any
daily |close / previous close - 1| above 25% is flagged with symbol, date, return and volume. You compare each flag with the NSE
corporate-actions listing; M2 rules each one (genuine move, or an unadjusted split, bonus or demerger). An unresolved flag excludes the
symbol; a genuine crash is never masked (hiding disasters would bias every long-only result upward).

## 4. Rules files (versioned, with sources and the retrieval date 2026-10-29)

- `rules/IN-equity-costs-v1.json` (delivery trades; as shown on Upstox and Zerodha pages): brokerage up to INR 20 per executed order
  (Upstox); STT 0.1% on buy and on sell; stamp duty 0.015% on buy; exchange transaction charge about 0.003% per side (Zerodha lists
  0.00307% for NSE; Upstox's rate not found: confirm); SEBI fee INR 10 per crore; GST 18% on brokerage, exchange and SEBI charges and
  on the DP charge; DP charge about INR 20 plus GST per scrip sold (Upstox pages show 18.5 to 20: use 20); slippage per side, base
  0.05% and stress 0.10% (ASSUMPTIONS for liquid mid caps, to be replaced by a measurement); position value per trade, default INR
  100,000 (the owner states the real figure). A function returns the round-trip cost fraction for a position value and a case. Self-test
  by hand: about 0.22% in percentage charges plus about INR 71 fixed, i.e. 0.29% at INR 1 lakh and 0.24% at INR 5 lakh before slippage;
  optionally the owner checks one sample trade in Upstox's own brokerage calculator and pastes the figure.
- `rules/IN-tax-v1.json`, `confirmed_by_owner: false`: listed equity bought and sold on delivery (STT paid): short-term (held up to 12
  months) 20%; long-term (over 12 months) 12.5% on gains above INR 125,000 per financial year; cess 4%; surcharge not modelled (it
  depends on income); loss set-off and carry-forward rules and the treatment of intraday trades: to be confirmed; financial year
  starts 04-01. M2 is not a tax advisor: the owner confirms every rule with a tax professional. In this phase only the file and a
  schema validator exist; the after-tax layer is built in Work Order 1.9 with the first candidate reports.

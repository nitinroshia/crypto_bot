## 1. Definition (two families: `S2-ETHUSDT` on ETH/USDT spot, `S2-BTCUSDT` on BTC/USDT spot; same code)

1. **Observations.** The 8h-aligned settlements (00:00, 08:00, 16:00 UTC) from `funding.py`. An observation's rate
   is the sum of native rates settled in (s-8h, s]; a window with a missing native settlement is masked and
   counted. The first settlement of each series is masked by construction.
2. **Predictor.** `rank_s` = (count of the 270 previous slots strictly below the current value + 0.5 x count exactly
   tied) / 270, current excluded (mid-rank). R2 applies: the 270 previous slots must all be valid; if any is masked
   the origin is excluded and counted. Report the tie share (fraction at the modal value, to the cutoff; expect
   about 39.6% ETH and 40.1% BTC) as a check. Strict-below and at-or-below ranks are labeled robustness columns on
   the primary cell only, never the primary statistic.
3. **Target.** Spot log return from the open of the 1h bar labeled s+1h to the open of the 1h bar labeled
   s+1h+H, with H = 24h and 72h in clock time.
4. **Cells and test.** Two cells (H = 24h, 72h). Primary: 72h. OLS slope of forward return on rank over all origins
   of the common set, Newey-West HAC with 3 lags for 24h and 9 for 72h. Direction NEGATIVE (higher funding, lower
   forward return); p-values are one-sided in the negative direction; Holm within the 2 cells. Report slope, HAC SE,
   correlation, HAC t, one-sided p, Holm, Bonferroni and MDE (2.486 x HAC SE), as in the S1 report. Descriptive,
   exploratory only: mean forward return and its excess over the unconditional mean at the same horizon for
   rank <= 0.10 and rank >= 0.90, with counts.
5. **Origins (one common set per pair, the intersection by entry time of both cells).**
   - First usable origin per R2: slot 272 counting the masked first settlement as slot 1, i.e. first settlement +
     271 x 8h. If the first settlements are at 00:00 UTC (confirm with `funding.describe_native()["first_settlement"]`
     and report the exact timestamps): BTC 2019-12-09 08:00 UTC, ETH 2020-02-25 08:00 UTC.
   - Last origin: the last settlement s with s + 1h + 72h <= 2025-08-31 23:00 UTC (the last usable 1h bar), which is
     2025-08-28 16:00 UTC. Confirm.
   - An origin whose entry bar (labeled s+1h) or exit bar (labeled s+1h+H, either H) is missing from the 1h file is
     excluded and counted, not imputed.
   - Sanity targets before gap exclusions, if the first settlements are at 00:00: about 6,269 origins and 23 full
     90-day blocks for BTC, about 6,035 and 22 for ETH; 270 origins per full block when nothing is excluded. Explain
     any material difference.
6. **Cutoff.** The discovery loader hard-truncates at 2025-08-31 23:59:59 UTC before any computation (funding
   settlements up to 2025-08-31 16:00, 1h bars up to label 23:00). The report states the number of post-cutoff rows
   in the discovery frame (must be 0).

## 2. Stability, by-year, economic gate

- **Stability** (Work Order 1.5 section 3, S2 variant, with answer-04's rulings). Blocks are 90 calendar days tiled
  from the first origin, per-block index sets, partial block never scored; centre x and y over the WHOLE common
  origin set including the partial block's origins; d = -1; null = circular time-shift of the rank vector against
  the target vector over the whole common origin set, minimum shift 300 settlements, R = 2000, seed stored;
  `y` = forward return divided by sigma30, where sigma30 is the standard deviation of the target pair's last 30
  daily log returns using only daily closes at or before the origin time (for the three settlements of a day, the
  previous day's close). Past-only: no future volatility may scale the target. Pass: p_stab < 0.05, then Holm
  across candidates per pair (R1): S1 and S2 are both in that family, S1's failure included.
- **By-year and leave-one-year-out** on the primary cell (72h), with the 120-day rule. Years with fewer than 120
  days are shown, not judged (BTC's 2019 will be one).
- **Economic gate at stress cost** (0.15% per side; pooled net return > 0 AND at least 70% of full blocks
  non-negative; blocks as above). The pre-registered rule: long from the open of the 1h bar labeled s+1h while the
  latest rank <= 0.5, otherwise cash, re-evaluated at each settlement. Interpretations that this order fixes:
  if the latest settlement has no valid rank (masked or gap-excluded), the position is cash until the next valid
  settlement; if a position change falls on a missing 1h bar it executes at the next available bar's open, is
  counted and reported; the segment starts flat at the first origin and is forced to exit at the last discovery
  bar's close, labeled "end-of-sample exit". Report buy-and-hold on the same segment, blocks and stress cost (R4 as
  ruled), trades, hit rate and exposure.

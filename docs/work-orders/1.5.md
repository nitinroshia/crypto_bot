## 2. Rulings

- **R1, Holm across candidates.** At every step that uses an across-candidate Holm (stability, holdout), the
  family is every non-void candidate that has a record at that step, per pair, whatever its outcome and
  whether or not it later moved on. A candidate that advances stays in the earlier step's family; a failure
  stays too. Key records by (family, step), not "latest record per family". `holm_at_step` must change
  accordingly. The within-family Holm (the 10 S1 cells, the 2 S2 cells) is separate and unchanged.
  `cumulative_count` is still distinct non-void families; also report the number of cells.
- **R2, S2 first usable origin.** Count valid observations only. The masked first slot is not an
  observation. The rank uses 270 valid previous observations, so the first usable origin is the 272nd slot
  counting the masked first settlement as slot 1, i.e. first settlement + 271 x 8h. If the first settlements
  are 00:00 UTC (confirm with `funding.describe_native()["first_settlement"]` and report the exact
  timestamps): BTC 2019-12-09 08:00 UTC, ETH 2020-02-25 08:00 UTC. If any of the 270 window observations is
  masked, the origin is excluded and counted.
- **R3, opposite-block veto: retired.** At 90 origins a single block has almost no power, so a veto can only
  fire by chance (even perfectly calibrated, "any of 30 blocks significant at 5% two-sided" fires 53% of the
  time under the null; calibrated by simulation it still false-vetoed 11-16% of null S2 paths). The
  non-stationarity rule (by-year / leave-one-year-out) and the economic gate's block rule cover regime flips.
- **R4, economic-gate reporting.** Next to the strategy's pooled net return and share of non-negative full
  blocks, report buy-and-hold over the same origins (pooled return and share of non-negative blocks). The
  gate itself is unchanged. A long/flat rule on a rising asset passes "pooled > 0" without any skill, so
  this is how the figures get interpreted.

## 3. Stability check, new definition (S1 and S2; reference code attached)

- Blocks: B full non-overlapping blocks of n = 90 days from the common origin set; the final partial block
  is dropped.
- Block score: `c_b = d * sum over origins t in block b of xt * yt`, where xt and yt are deviations from
  their means over the whole common origin set (no per-block intercept), and y is the forward return
  divided by sigma30 at the origin (for S2, the trailing 30-day sd of the target pair's daily log returns at
  the origin's day). d = +1 for S1, d = -1 for S2, so that positive means "agrees with the pre-registered
  direction".
- Null: R = 2000 replicates produced by the pipeline's own code.
  - S1: stationary block bootstrap of the daily log returns of the discovery series (mean block length 20
    days); rebuild predictor and target from each resampled path with your production code, at the same
    origin positions. The discovery loader's cutoff truncation applies as always.
  - S2: circular time-shift of the funding-rank vector against the target vector by a random offset of at
    least 300 settlements from zero. The rank vector is computed once from the real funding series.
  - A time-shift null is NOT valid for S1 (predictor and target come from the same price series). Do not
    use it there.
- Combine: `mu_b`, `sd_b` = mean and std of `c_b` over the replicates; `s_b = (c_b - mu_b) / sd_b`;
  `T = sum(s_b) / sqrt(B)`; `p_stab = (1 + #{replicates with T_r >= T_obs}) / (R + 1)`, with `T_r` built
  from the same `mu_b`, `sd_b`. Pass: `p_stab < 0.05`, then Holm across candidates per R1.
- Store in the registry record: T, p_stab, R, seed, mean block length (S1) or minimum shift (S2), B.

## 4. Acceptance tests (synthetic; the production code must meet these bands)

| Test | Band |
|---|---|
| S1 null, Gaussian iid, B=30, n=90 | false-pass <= 7% |
| S1 null, t(3) returns + persistent volatility clustering | false-pass <= 7% |
| S1 injected momentum edge, pooled HAC t about 5 (reference a=0.006) | pass >= 70% |
| S1 injected strong edge, pooled HAC t about 11 (reference a=0.012) | pass >= 95% |
| S2 null, Gaussian; and t(3) + volatility clustering, B=22, n=270 | false-pass <= 7% |
| S2 injected edge, correlation about -0.16 (reference a=0.003) | pass >= 80% |

Reduced size (60 paths, R=500) runs in a couple of minutes; `--full` (200 paths, R=1000) is the real
acceptance run. Reference results from my runs: S1 null 0.8-1.7%, t3+SV null 0%, edge 83-87% and 100%; S2
null 4-5% and 1-2%, edge 100%. For orientation only: S2's power at a realistic correlation of -0.03 is
about 20%, so a real but small S2 effect will usually come back "inconclusive". That is a data-length
limit, as noted in section 10, not a defect. If a band cannot be met, report to me; do not move the bands
and do not improvise a different statistic.
